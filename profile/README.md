# 🔬 CONMED Advanced Surgical Engineering

Welcome to the **CONMED Advanced Surgical GitHub Organization**.

This organization supports software, firmware, automation, engineering tools, test infrastructure, and technical collaboration for Advanced Surgical product development.

It is intended to be the engineering home for repositories that support Advanced Surgical product development, sustaining work, prototyping, verification support, and long-term software maintainability.

---

## 🎯 Mission

Our mission is to help develop safe, reliable, maintainable, and innovative technologies that support surgical teams and improve patient outcomes.

This GitHub organization helps Advanced Surgical teams work more effectively by providing a centralized place for:

- Product software
- Embedded firmware
- Engineering utilities
- Test automation
- Verification and validation support tools
- Data analysis scripts
- Build and release support
- Documentation stored near the codebase
- Early concept and prototype development

---

## 🧑‍💻 Engineering Workflow

Advanced Surgical repositories should use modern engineering workflows that support collaboration, review, quality, and traceability.

Typical expectations include:

- Use Git for version control
- Create branches for new work
- Submit Pull Requests for review
- Request peer review before merging
- Keep repository documentation current
- Follow applicable coding and cybersecurity expectations
- Keep regulated or project-specific work aligned with approved CONMED processes

Repository-specific instructions should be followed when available.

## 🚦 Recommended Repository Structure

Individual repositories may vary, but a well-organized repository often includes:

```text
repository-name/
├── .github/
│   ├── workflows/
│   └── PULL_REQUEST_TEMPLATE.md
├── docs/
├── src/
├── tests/
├── tools/
├── scripts/
├── README.md
├── CONTRIBUTING.md
└── CHANGELOG.md
```

Not every repository needs every folder. The structure should fit the project while keeping the repository easy to understand and maintain.

## 🔁 Pull Request Expectations

Pull Requests should be clear, reviewable, and traceable.

A good Pull Request generally includes:

- What changed
- Why the change was made
- How the change was tested
- Any risks, limitations, or follow-up work
- Links to related issues, requirements, or work items when applicable

Before requesting review, contributors should confirm that the relevant build, test, analysis, or documentation updates have been completed.

---

## 🤖 GitHub Copilot and AI-Assisted Development

GitHub Copilot may be used as an engineering productivity tool when available and approved.

Recommended uses include:

- Explaining unfamiliar code
- Drafting documentation
- Generating unit test scaffolding
- Suggesting refactoring approaches
- Helping with repetitive coding tasks
- Improving onboarding to existing repositories

Important expectations:

- Engineers remain responsible for the final output
- AI-generated code must be reviewed and tested
- Do not rely on AI-generated output without verification
- Do not expose secrets, credentials, or restricted information to unapproved tools
- Follow applicable CONMED procedures and project-specific requirements

## 🛡️ Quality, Safety, and Compliance

Advanced Surgical engineering work may support regulated medical device development.

Contributors should ensure their work supports:

- Safe and reliable product behavior
- Clear software traceability where applicable
- Maintainable architecture and implementation
- Appropriate review and approval
- Cybersecurity awareness
- Verification and validation readiness
- Alignment with applicable CONMED quality processes

When in doubt, ask the project owner, engineering lead, quality representative, or repository maintainer before proceeding.

## 🌱 New Contributors

If you are new to this organization, start here:

1. Confirm you have access to the correct repositories
2. Review the repository README
3. Review any CONTRIBUTING.md file
4. Set up the required development tools
5. Build or run the project locally when applicable
6. Review open issues or assigned work
7. Create a branch for your changes
8. Submit a Pull Request when ready for review

A good first contribution is small, clear, documented, and easy to review.
